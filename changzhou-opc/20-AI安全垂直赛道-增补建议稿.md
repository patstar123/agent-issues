# AI+安全垂直赛道：第（二十）条增补建议稿

> 本文是单独起草的增补建议，不替代原十条整理稿。  
> 序号按来稿保留为（二十）。第（十九）条不在本次范围内。  
> 原第（四）条已按正文改为知识产权保护，不能再拿来充当“数据安全”或本条的 AI 安全赛道。

---

## 一、提议说明

**提议人意见：** 在特色产业方向上，单列 **AI+安全** 垂直赛道，并写清细分口径。目标不是再发一笔泛泛的“安全补贴”，而是把常州本地安全企业往 OPC 园区聚拢，形成可识别的安全产业集群。

口径上，先明确三块：

1. **数据安全**
2. **模型安全**（含私有化部署与调优、AI 内容识别等）
3. **智能体安全**

在此基础上，再补两类当前最容易出事、也最能做出产品的方向：

4. **MCP 数据调用安全**
5. **大模型调用安全**（含脱敏等行业场景）

原十条的重点领域写的是“AI+制造”、AIGC、跨境电商，没有把安全写成赛道。本地安全企业若只按综合 OPC 政策来申报，既看不出园区要什么，也不会因此搬家。本条就是把“要什么、聚谁、怎么认”写清楚。

---

## 二、建议写入讨论稿的条文

### 五、垂直赛道

**（二十）鼓励 AI+安全方向集聚。** 将人工智能安全列为 OPC 标杆社区重点垂直赛道，明确覆盖数据安全、模型安全（含私有化部署与调优、AI 内容识别、生成内容溯源、模型供应链安全等）、智能体安全，以及 MCP 数据调用安全、大模型调用安全（含脱敏等行业应用）。支持常州本地安全企业、安全类 OPC 向园区集聚，对符合细分口径并在我区注册经营、设立研发或交付团队的，在社区入驻、场景开放、算力支持和专用基金评审中予以优先。

## 三、细分口径（建议写入实施细则或申报指南）

下列口径用于认定“是不是 AI 安全项目”，也用于对外招商时说明园区要什么。建议认定时 **命中其中一类即可**，不要求六类做全。

| 序号 | 细分方向 | 覆盖什么 | 典型产品 / 能力 |
| --- | --- | --- | --- |
| 1 | 数据安全 | 训练、微调、推理、运营全链路的数据分类分级、访问控制、泄露防护、审计留痕 | 数据防泄漏、权限与审计、安全运营 |
| 2 | 模型安全 | 模型全生命周期安全：私有化部署与调优、AI 内容识别、生成内容溯源、对抗与越狱防护、供应链与后门检测、输出安全、权重保护、上线评测 | 见下文“模型安全重点方向” |
| 3 | 智能体安全 | Agent 的工具调用、权限收敛、越权操作、任务链审计、失控熔断 | Agent 网关、权限沙箱、操作审计 |
| 4 | MCP 数据调用安全 | 经 MCP 等协议访问本地文件、数据库、企业系统和第三方工具时的鉴权、最小权限、调用审计、防数据外带 | MCP 网关、工具白名单、调用审计 |
| 5 | 大模型调用安全 | 调用公有或私有大模型时的输入输出管控，**含脱敏**、提示词注入防护、越权提问拦截、输出合规 | 模型网关、提示词防火墙、调用审计 |
| 6 | 行业脱敏与合规 | 面向制造、政务、金融、医疗、跨境等场景的脱敏、匿名化、最小化使用和合规交付 | 行业脱敏组件、合规一体机 |

**口径说明：**

- **模型安全** 不要只写“私有化部署调优”。部署只是交付形态；内容真伪、开源模型是否被投毒、输出会不会失控，都是模型本身的安全问题，也是本地安全企业更能做成产品的方向。
- **MCP 数据调用安全** 不要并进“智能体安全”一笔带过。MCP 已经是 Agent 接企业数据的常见通道，风险在“工具一接上、数据就被带出去”，需要单独认、单独招。
- **大模型调用安全** 和 **脱敏** 绑在一起写：企业把图纸、客户名单、工艺参数送进模型前后，都要能脱敏、能拦截、能审计。这是最容易做出可售产品的一块。
- 六类可以交叉，但申报时建议主报一类，避免一个项目占满所有优先通道。

### 模型安全重点方向（建议写进申报指南）

模型安全建议再往下拆，认定时 **命中其中一子类即可**。优先看有没有可交付产品或可核验能力，不看概念词。

| 子方向 | 要解决什么 | 和常州场景怎么接 | 建议优先级 |
| --- | --- | --- | --- |
| **AI 内容识别** | 判别文本、图像、语音、视频是否由 AI 生成，识别换脸、伪声、伪造证件和伪造商品图 | 服务企业宣传 / 出海 / 广告打假，以及跨境电商、政务核验 | 高，建议正文点名 |
| **生成内容溯源与数字水印** | 生成时嵌入不可见水印或来源标记，事后能追到模型、账号或批次 | 和内容识别配套：先“标得出”，再“认得出”；也对接原（四）知识产权 | 高 |
| **私有化部署与调优** | 模型在本地或专有云落地，行业微调，接口和权重不外送 | 制造、政务客户普遍要求私有化，是本地安全企业的现成订单 | 高，原文已点名 |
| **对抗攻击与越狱防护** | 防提示词越狱、对抗样本、恶意指令把模型打穿 | 企业把模型接到客服、质检、办公系统后几乎都会遇到 | 高 |
| **模型供应链安全** | 开源或外购模型的来源核验、投毒和后门检测、组件扫描 | 大量 OPC 会直接拉开源权重，中毒模型进园区的风险很高 | 高 |
| **模型输出安全与行业对齐** | 违规输出拦截，关键行业里压幻觉、控口径 | 智造质检、客服、跨境文案都不能“模型说了算” | 中高 |
| **模型资产与权重保护** | 防模型窃取、接口刷取、权重泄露，保护私有化成果 | 和私有化部署绑定，否则调优成果被人拖走 | 中 |
| **模型安全评测与上线检测** | 上线前做安全基准、红队和回归，上线后持续监测 | 园区可做成公共能力，比每家 OPC 自己搭一套更合适 | 中，适合社区公共服务 |

**取舍备注：**

- **AI 内容识别** 和“做 AIGC 内容”不是一类。生成走原重点领域 AIGC 和第（九）条；识别真伪、打假、溯源才进本条。一个项目不能既按内容创作领传播奖，又按安全赛道占优先权，除非能力确实分开、主报一类。
- **内容识别** 和 **调用安全** 也要分开：调用安全管的是“送进模型的数据出不出得去”；内容识别管的是“这段图文声像是不是假的、是不是 AI 做的”。
- 深度伪造检测、AI 生成检测、伪造商品图识别，建议都归在 **AI 内容识别** 下，不必再单列赛道。
- 多模态（图、声、视频）是内容识别的能力深度，不是新赛道。申报指南可写“鼓励覆盖图像、语音、视频，不强制四模态做全”。
- 模型安全评测更适合做成社区或园区公共能力（和算力券、语料券并列的“测评券”），不必要求每家小 OPC 都自建评测平台。

## 四、各块怎么落地（备注与建议）

### 1. 本条要吸引的是谁

优先对象建议写成：

- 常州已有网络安全、数据安全、信创安全企业，向 AI 安全转型或增设 AI 安全产品线，并迁入或新设在 OPC 园区；
- 安全类 OPC（一人或小团队），产品落在上表任一细分；
- 外地安全团队来常设立研发、交付或联合实验室，核心人员常驻园区。

**备注：** “本地安全企业向园区汇聚”是本条的政策目标，认定和奖励都应围绕 **入驻、设团队、在区纳税或交付**，不要只奖一篇方案、一次签约意向。

### 2. 和原十条怎么衔接，尽量少开新口子

本条先解决“赛道认定”，真金白银尽量复用已有条款，认定后给予 **优先权**：

| 已有条款 | 对 AI 安全项目怎么用 |
| --- | --- |
| （一）标杆社区 | 安全类 OPC 和本地安全企业优先入驻，可考虑在社区内划出“AI 安全专区”或安全工位 |
| （三）公共算力 | 私有化部署、调优、攻防测评产生的算力、语料、模型费用，优先兑付算力券 / 模型券 |
| （五）专用基金 | 符合细分口径的小团队，按小额、低门槛优先评审；安全企业体量较大的，走现有产业基金，不占 OPC 小额额度 |
| （八）场景开放 | 区内企业采购 AI 安全产品（网关、脱敏、私有化加固、MCP 管控、内容识别、水印溯源等）可计入高价值场景 |
| （九）AIGC 企业应用 | 对企业出海、宣传、广告及视听内容，可要求或优先采用内容识别、水印溯源，防止仿牌、假素材和伪造流量 |
| （十二）至（十八） | 夜校、训练营可单列“AI 安全”方向，出题方优先本地安全企业和智造场景企业 |

**备注：** 若一定要单列安全专项奖，建议只奖“新迁入园区并实际经营”的本地安全企业，一次性、有上限，并与空间免租、算力补贴“从高不重复”。金额原文没有，是否单设请区里拍板，本文不编造。

### 3. 建议对外发布的一句话招商口径

> 常州高新区 OPC 社区开放 AI+安全赛道，聚焦数据安全、模型安全（私有化部署调优、AI 内容识别、内容溯源、供应链安全）、智能体安全、MCP 数据调用安全、大模型调用安全（含脱敏），欢迎本地安全企业带团队、带产品入园。

这句话可直接用于社区手册、一网通办专区和招商材料，避免只写“支持人工智能安全”这种空词。

### 4. 认定时建议卡住的几条底线

- 只做传统防火墙、机房运维、等保咨询，与模型、智能体、大模型调用无关的，**不按本条认定**，可走现有安全或软件政策。
- 只做通用聊天机器人、内容生成，没有安全防护或内容识别能力的，走 AIGC 口径，不占安全赛道优先权。
- 私有化部署必须有实际交付对象或可核验的部署环境，不能只写“支持私有化”。
- AI 内容识别应能说明识别对象（文本 / 图像 / 语音 / 视频）、可核验的准确率或试用场景，不能只写“支持鉴定”。
- MCP / 大模型调用安全应能说明：拦什么数据、记什么日志、脱敏做到哪一层（输入、输出，或行业字段级）。

## 五、建议的板块关系

```text
原十条重点领域：AI+制造、AIGC、跨境电商
增补垂直赛道：AI+安全
        ├── 数据安全
        ├── 模型安全
        │     ├── 私有化部署与调优
        │     ├── AI 内容识别（含深度伪造 / AIGC 检测）
        │     ├── 生成内容溯源与数字水印
        │     ├── 对抗攻击与越狱防护
        │     ├── 模型供应链安全（投毒 / 后门 / 开源扫描）
        │     ├── 输出安全与行业对齐
        │     ├── 模型资产与权重保护
        │     └── 安全评测与上线检测
        ├── 智能体安全
        ├── MCP 数据调用安全
        └── 大模型调用安全（含脱敏等行业领域）
```

- 与原（四）：（四）是版权和知识产权，本条是安全产业赛道，两件事情，不要合并。
- 与原（八）：智造场景里，工厂数据上模型和 Agent 接产线系统，正好是脱敏、MCP 调用、私有化部署的需求方；商品图、宣传片、质检影像则是内容识别的需求方。
- 与原（九）：内容奖励若配识别和水印，既防刷量伪造，也给安全类 OPC 本地订单。
- 与第（五）条建议稿：安全类 OPC 用小额专用基金；本地中型安全企业用现有产业基金或跟投，避免 1 亿元小额盘子被少数大项目占满。

## 六、还需要拍板的事项

1. 本条是作为特色创新下的第十一条，还是单列“垂直赛道”板块第（二十）条。来稿从 20 起号，本文按 **另板块增补** 处理。
2. 是否在某个标杆社区明确挂“AI 安全专区”，作为本地安全企业的物理汇聚点。
3. 认定后是只给“优先权”（入驻、算力、基金、场景），还是再单设迁入奖。
4. 第（十九）条如有其他垂直赛道（例如更细的制造或跨境），与本条并列，不要塞进安全口径。
